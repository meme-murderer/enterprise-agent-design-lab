# Facilitator guide

**AICC 2026 · Content created by Vetitek**

The supplied talk was delivered immediately before the lab. It establishes attribution, limits, and recovery; the exercise applies those questions to one process. The schedule below is a suggested 45-minute lab, excluding the talk.

| Minutes | Activity                                          | Prompt or purpose                                                                                                            |
| ------- | ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 0–3     | Frame the exercise and safety boundary            | “We are deciding what authority is justified. Use a hypothetical process.”                                                   |
| 3–8     | Scripted poisoned-document demonstration          | Ask what could go wrong before revealing the attempted action and approval boundary. Explain that no tools actually execute. |
| 8–10    | Orient participants and choose a process          | Teach the four outcomes. Pair participants if useful.                                                                        |
| 10–20   | Complete the guided intake and inspect the canvas | Ask participants to locate the rule that shaped the recommendation.                                                          |
| 20–27   | Failure exercise and stop-rule revision           | “What failure would make you change this plan? Who stops the test, and what triggers the stop?”                              |
| 27–36   | Compare prepared or voluntarily shared examples   | Use the invoice detectability pair. Change one condition and ask why authority changes.                                      |
| 36–42   | Discuss a next step                               | “What would you need to learn before running even a small simulation?”                                                       |
| 42–45   | Takeaway and close                                | Copy or print the decision record; revisit the owner, approval boundary, and stop rule.                                      |

## Before the session

Open `/lab`, `/facilitator/demo`, `/facilitator/injection`, and `/takeaway` on the server you control. Use `/review/all-screens` to inspect the experience without completing it. A remotely hosted deployment needs network access; for an internet-independent demonstration, start and check the app locally in advance.

Use only prepared examples for projection until you have privately checked any shared submissions. Keep the facilitator PIN off the projector. If you offer sharing, explain that it is optional, what the completed canvas contains, and that the current app retains it until facilitator purge. Decide and communicate a deletion schedule before collecting material.

## Facilitation choices

The app permits copying, printing, and opening an email draft before the optional failure exercise. Do not describe the revision as technically mandatory. Encourage participants to do it because identifying and changing a weak boundary is a central learning objective.

Treat “Limited agent simulation” as a proposal to explore a bounded offline test, not a production recommendation. Ask participants what evidence is missing. Do not present the rubric as universally applicable policy.

Useful discussion questions:

- Which fact most influenced this recommendation?
- Could fixed rules or a drafting assistant achieve the same outcome?
- Would the team find an error before it affects someone?
- Does the stop rule identify something observable, an owner, and a response?
- What changed after considering failure?

## If something fails

If model generation fails, the current v2 flow can supply a standard plan. Explain the fallback rather than presenting it as personalized analysis. If sharing is unavailable, continue with prepared examples or a participant reading a sanitized summary aloud. If the hosted app is unavailable, use a locally prepared demonstration and the printed questions. Do not improvise a workaround that asks participants to disclose sensitive material.
